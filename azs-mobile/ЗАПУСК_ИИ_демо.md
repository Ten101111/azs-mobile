# Запуск демонстрации ИИ — пошагово

Всё выполняется на вашем компьютере. Корпоративная сеть и реквизиты хранилища
не нужны: демонстрация работает на локальной базе агрегатов.

Откройте терминал и перейдите в папку проекта — все команды выполняются отсюда:

```bash
cd ~/Downloads/"Классификатор АЗС"/azs-mobile
```

---

## Шаг 1. Проверить модель

```bash
ollama list
```

**Должно появиться:** таблица с загруженными моделями. Имя нужной должно совпадать
со строкой `AI_MODEL` в `.env.local` — сейчас там `qwen3.8:latest`. Если в
`ollama list` имя другое, поправьте `.env.local`.

**Если команда ничего не выводит или виснет** — Ollama не запущена. Откройте второе
окно терминала и выполните `ollama serve`, оставьте его работать.

---

## Если запускали туннель и получили «No module named uvicorn»

Так было до 21.09.2026: `scripts/start-tunnel.sh` звал системный `python3`,
а это Homebrew 3.14, где зависимостей бэкенда нет и быть не может — под 3.14
нет сборок `pandas` и `psycopg2`. Теперь скрипт сам берёт `.venv/bin/python`,
а если окружения ещё нет — подсказывает собрать его и не запускается молча.

Если сообщение всё же появилось, значит окружение не собрано. Соберите его
один раз:

```bash
npm start
```

Эта команда создаёт `.venv` на Python 3.11–3.13 и ставит зависимости.
После неё туннель запускается как обычно:

```bash
./scripts/start-tunnel.sh
```

Тем же окружением теперь пользуются `npm run backend`, `npm run test:backend`
и скрипты выгрузок — через резолвер `scripts/python.sh`. Голый `python3`
остался только у `npm start`: он и должен запускаться любой версией, потому
что его работа — собрать правильное окружение.

---

## Шаг 2. Собрать окружение Python

Homebrew обновил системный Python до 3.14, а зависимости бэкенда установлены под
предыдущую версию — поэтому приложение и не запускается. Ставить всё в 3.14
нельзя: в `requirements.txt` закреплены `pandas==2.2.3` и `psycopg2-binary==2.9.10`,
готовых сборок под 3.14 для них нет. Нужно отдельное окружение на 3.11–3.13.

```bash
for V in 3.13 3.12 3.11; do
  P=$(command -v python$V) && { echo "Беру Python $V: $P"; break; }
done
[ -z "$P" ] && echo "Подходящей версии нет — выполните: brew install python@3.12"

"$P" -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r backend/requirements.txt
python -c "import fastapi, uvicorn, sqlglot, pandas; print('всё на месте')"
```

**Должно появиться:** `всё на месте`

**Если написало «Подходящей версии нет»** — сначала `brew install python@3.12`,
затем блок целиком заново.

> **Важно для всех следующих шагов.** В каждом новом окне терминала сначала
> выполняйте `source .venv/bin/activate`. После этого `python3` — это питон
> окружения, и `npm run dev:full` подхватит именно его.

## Шаг 3. Собрать справочник объектов

```bash
python3 backend/ai/build_reference.py
```

**Должно появиться:**
```
ai_reference.sqlite3: 2770 объектов, из них 2378 с назначенным ТМ
```

Команда читает `data/stations.json` и складывает плоскую таблицу объектов
в `data/ai_reference.sqlite3`. Выполняется один раз и после каждого обновления
справочника. База показателей при этом не изменяется.

## Шаг 4. Самопроверка контура

```bash
python3 -m backend.ai.selfcheck
```

**Должно появиться семь строк, все со знаком `ok`:**
```
  ok   │ Библиотека sqlglot — версия 30.18.0
  ok   │ База показателей — kpi_metrics.sqlite3, 469 МБ
  ok   │ Справочник объектов — 2770 объектов
  ok   │ Валидатор SQL — 3 допустимых и 7 опасных запросов
  ok   │ Изоляция области данных — вся сеть 2485, ТМ 27 из 27, обход не прошёл
  ok   │ Ollama — загружено моделей: …
  ok   │ Модель qwen3:8b — готова
  ok   │ Живая генерация — 3 из 3 вопросов отработали как ожидалось
```

Что проверяется: валидатор отбивает `DROP TABLE`, `UPDATE`, две инструкции через
точку с запятой, обращение к `auth_users`, попытку достать `password`, `PRAGMA`
и `ATTACH` чужого файла. Изоляция области проверяется четырьмя способами обхода.

**Если «Модель не найдена»** — имя в `AI_MODEL` не совпадает с выводом `ollama list`.

**Если «Живая генерация» не прошла** — модель выдала SQL, который не принял
валидатор. Пришлите мне вывод: скорее всего в контракт нужно дописать примеры
под то, как формулирует именно ваша модель.

## Шаг 5. Демонстрационный сценарий

```bash
python3 -m backend.ai.demo
```

**Должно появиться:** шесть вопросов подряд, по каждому — сгенерированный SQL,
таблица с цифрами и время. Последний вопрос «Удали таблицу stations» должен
закончиться отказом валидатора.

Этого уже достаточно, чтобы показать работу контура без интерфейса.

---

## Шаг 6. Включить раздел в приложении

Добавьте одну строку в конец файла `.env.local`:

```
AI_DEMO_ENABLED=1
```

Проверьте заодно, что там есть строка `ADMIN_EMAILS` с вашей почтой — той самой,
под которой вы входите в приложение. Если строки нет, администратором считается
только `artem.manokhin@lukoil.com`, и раздел не появится.

## Шаг 7. Запустить всё одной командой

```bash
cd ~/Downloads/"Классификатор АЗС"/azs-mobile
npm run dev:full
```

Одна команда, одно окно терминала. Запускать из-под активированного окружения
не нужно — скрипт сам находит `.venv`, а если его нет или он сломан, собирает
заново. Он же доставит недостающие библиотеки, поставит зависимости фронтенда,
соберёт справочник объектов и проверит, отвечает ли Ollama.

**Должно появиться:**
```
Режим: DEV   Python: …/.venv/bin/python
Фронтенд:   http://localhost:5174/
Бэкенд:     http://localhost:8000/api/health
ИИ-раздел:  включён, модель qwen3.8:latest
Остановить оба процесса — Ctrl+C.
```

Строка про ИИ-раздел сразу скажет, если что-то не так: выключен флаг, не
запущена Ollama или имя модели не совпадает с загруженными.

Откройте `http://localhost:5174`, войдите под своей учётной записью и перейдите
в **Аналитика → ИИ-аналитик**.

Именно `dev:full`, а не `npm start`: в режиме PWA собирается service worker,
который кэширует приложение офлайн. Для показа это лишний риск — после правки
кода браузер может показать старую копию.

## Что показывать

Порядок, в котором контур выглядит убедительнее всего:

1. **Обычный вопрос.** «Выручка НТУ по моим АЗС за август 2026» — приходит таблица.
   Раскройте «Как это посчитано» и покажите сгенерированный SQL.
2. **Сложнее.** «Сравни объём топлива за август 2026 с августом 2025» — модель
   сама строит сравнение двух периодов.
3. **Главное.** Один и тот же вопрос под администратором и под территориальным
   менеджером. Цифры разные, и в SQL видно, откуда берётся разница: система сама
   дописала ограничение по объектам менеджера. Пользователь снять его не может.
4. **Отказ.** «Удали таблицу stations» — валидатор отбивает запрос до обращения
   к базе, отказ попадает в журнал.

Полезно проговорить: модель — заменяемая деталь, её потом поменяют на ту, что
будет развёрнута в контуре ЛИКАРДа. Защита держится не на ней, а на валидаторе.

## Если что-то пошло не так

| Что видите | Что делать |
|---|---|
| `ModuleNotFoundError: sqlglot` | Вернуться к шагу 2 |
| `Справочник объектов — нет файла` | Вернуться к шагу 3 |
| `Ollama не отвечает` | В отдельном окне запустить `ollama serve` |
| `Модель не найдена` | Сверить `AI_MODEL` с выводом `ollama list` |
| `REQUEST_FAILED_502` | Бэкенд не поднялся. Причина будет в строках `[api]` в том же терминале |
| `HTTP ERROR 404` на localhost:5174 | Пропал `index.html` в корне проекта. Восстановить: `git checkout -- azs-mobile/index.html` |
| Вкладки «ИИ-аналитик» нет | Сначала жёсткая перезагрузка страницы: Cmd+Shift+R. Старый билд мог остаться в кэше service worker. Если не помогло — в DevTools → Application → Service Workers → Unregister, затем проверить `AI_DEMO_ENABLED=1` в `.env.local` |
| Страница открывается, но выглядит по-старому | Работает кэш service worker. Cmd+Shift+R или снять регистрацию в DevTools |
| Ответы приходят, но цифры странные | Прислать вопрос и SQL из блока «Как это посчитано» |

Подробности про устройство контура, настройки и переход на витрину в ОХД —
в `backend/ai/README.md`.
