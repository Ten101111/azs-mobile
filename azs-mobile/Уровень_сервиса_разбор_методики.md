# Уровень сервиса: разбор методики и что из неё берём в продукт

Источник: «Методика планирования и расчета производственно-коммерческих и сервисных показателей деятельности организаций нефтепродуктообеспечения в РФ» от 01.06.2026 (приложение к письму МД110Л от 08.06.2026), 59 стр. Разбор от 11.09.2026.

Документ утверждается приказом Генерального директора и является обязательным. Он закрывает вопрос №18 реестра и требует правок в макетах справок v0.2 и в БТ.

---

## 1. Главное в двух абзацах

«Уровень сервиса» (УС) — показатель премирования, построенный на оценках клиентов в мобильном приложении «АЗС ЛУКОЙЛ» по пятибалльной эмоциональной шкале. Средняя оценка за месяц делится на целевое значение, которое ежемесячно спускает БРН распорядительным документом. Три исхода: выполнен, частично выполнен, не выполнен.

Ключевое открытие для нашего продукта: **уровень сервиса — это не одно число на объект**. Он считается из разных наборов категорий оценок для разных ролей, и у одной и той же АЗС значение для работника АЗС, для менеджера комплекса и для ТМ будет разным. Второе открытие: при реальных целевых значениях (~4,99) механика «набери N пятёрок до цели», заложенная в наши макеты, математически верна, но практически бессмысленна — и её надо заменить.

## 2. Два разных показателя, которые легко спутать

| | **Уровень сервиса (УС)** | **Качество сервиса (КС)** |
|---|---|---|
| Что измеряет | удовлетворённость клиентов | степень недовольства клиентов |
| Формула | средняя оценка / целевое значение | (негативные оценки МП + жалобы ЕГЛ) на 100 тыс. чеков |
| Направление | чем больше, тем лучше | чем меньше, тем лучше |
| Для кого | РУ, ТМ, менеджеры комплексов, работники АЗС, АУП ОНПО и ЛИКАРД | **агенты и заправщики** |
| Результат | выполнен / частично / не выполнен | место в рейтинге → мультипликатор премии 100 / 50 / 0% |
| Периодичность | месяц (для РУ — квартал) | месяц, рейтинг 7-го числа |
| Раздел методики | 4 | 9 |

В БТ мы до сих пор говорили только об УС. КС — отдельный показатель, и именно он завязан на агентов; см. раздел 8.

## 3. Уровень сервиса: формулы

**Средняя оценка за месяц (СР):**

```
СР = Σ оценок / N оценок

Σ оценок = 1×кол-во«Очень плохо» + 2×кол-во«Плохо» + 3×кол-во«Хорошо»
         + 4×кол-во«Очень хорошо» + 5×кол-во«Отлично»
```

**Выполнение показателя (округление до тысячных):**

```
УС = СР / СРцел × 100%
```

Для региональных управляющих период — квартал: `СРру = Σ СРмес / 3`.

**Целевое значение (СРцел)** ежемесячно устанавливает БРН распорядительным документом, рассчитывая его как среднее значение показателя, достигнутое в предыдущем месяце совокупно по всем АЗС ОНПО РФ. Для РУ — ежеквартально по предыдущему кварталу.

> Важно: цель **общая для всех АЗС общества**, а не индивидуальная по объекту. В образце отчёта (Приложение №5) у всех АЗС стоит одно и то же целевое значение 4,987.

**Пороги выполнения (п. 4.5.7):**

| Значение УС | Статус | Коэффициент в отчёте |
|---|---|---|
| ≥ 100% | выполнен | 1 |
| 99,5–99,99% | частично выполнен | 0,5 |
| < 99,5% | не выполнен | 0 |

## 4. Какие оценки попадают в расчёт

- Оценки «Отлично» (5) и «Очень хорошо» (4) учитываются **всегда**, независимо от того, выбрал клиент категорию или нет.
- Оценки «Очень плохо» (1), «Плохо» (2), «Хорошо» (3) учитываются **только если указана категория, релевантная роли** (см. раздел 5). Без категории или с нерелевантной категорией — исключаются.
- Категория «Другое» не учитывается никогда, ни для одной роли.
- Не учитываются оценки по возвратным и отменённым транзакциям.
- Учитывается **одна оценка на одну АЗС по уникальной карте лояльности в сутки** при сумме чека более 100 ₽ (в том числе при оплате баллами).
- Для автоматических АЗС не учитываются категории «Обслуживание на кассе» и «Работа заправщика».
- Принадлежность АЗС для ОНПО: COCO, CODO, Арендованные.

**Как клиент ставит оценку** (справочно, раздел 11 методики): после покупки свыше 100 ₽ по карте лояльности — через PUSH сразу после оплаты либо в разделе «История операций» в течение 24 часов. Восемь категорий: Обслуживание на кассе, Чистота на АЗС, Товары кафе и магазина, Техническое состояние АЗС, Мобильное приложение, Другое, Программа лояльности, Работа заправщика. При оценках 1–2 указание хотя бы одной причины обязательно.

## 5. Категории зависят от роли — главное следствие для продукта

| Роль | Область расчёта | Категории оценок |
|---|---|---|
| Региональный управляющий | все закреплённые АЗС | касса, чистота, техническое состояние, заправщик |
| ТМ / менеджер комплекса / управляющий комплекса | все закреплённые АЗС | касса, чистота, заправщик |
| Менеджер / директор комплекса | конкретная АЗС | касса, чистота, заправщик |
| Работники АЗС | конкретная АЗС | касса, чистота |
| Управляющий шеф-повар | закреплённые АЗС | касса, чистота |
| Уборщик | конкретная АЗС | чистота |
| Наполнитель баллонов | конкретная АЗС | заправщик |
| АУП ОНПО (операционный отдел, сбыт, кадры, ОТиСП, АХО) | все собственные АЗС общества | касса |

**Что это значит для нас.** В витрине нельзя хранить один атрибут «уровень сервиса АЗС». Нужны либо предрассчитанные значения в разрезе ролевых наборов категорий, либо сырьё для пересчёта: количество и сумма оценок в разрезе «АЗС × месяц × категория × балл». Второе предпочтительнее — позволяет считать любой ролевой срез и показывать разбивку негатива по категориям.

## 6. Автоматическое выполнение — важнее формулы

Методика содержит три правила, которые перекрывают расчёт:

1. **Нет негативных оценок (1 и 2) за период** → показатель считается выполненным. Оценка «3» негативной в этом правиле не считается.
2. **Нет оценок вообще** → показатель считается выполненным.
3. **Статус «модернизация» или «реконструкция»** → выполнен; для комплексов и ТМ/РУ расчёт ведётся только по АЗС со статусом «Действующая».

Это подтверждается образцом отчёта: АЗС 99362 имеет УС 99,84% (формально «частично»), но ноль негативных оценок — и в отчёте стоит выполнение 1.

> **Операционный вывод, который и должен звучать в справке: задача персонала — не набрать пятёрок, а не получить ни одной оценки «1» или «2».**

## 7. Почему механику «сколько пятёрок до цели» надо убрать из макетов

В макетах справок v0.2 заложен расчёт «до цели — 56 оценок „5“, это 7 в день». На реальных значениях методики это не работает.

При целевом значении 4,987 вес одной пятёрки составляет всего 5 − 4,987 = 0,013 балла. Отсюда цена одной плохой оценки в дополнительных пятёрках:

| Полученная оценка | Сколько нужно дополнительных «5», чтобы её компенсировать |
|---|---|
| «1» Очень плохо | ≈ 307 |
| «2» Плохо | ≈ 230 |
| «3» Хорошо | ≈ 153 |
| «4» Очень хорошо | ≈ 76 |

Формула: `(Цель − оценка) / (5 − Цель)`.

Проверка на реальных данных Приложения №5: АЗС 99314, 645 оценок за месяц, средняя 4,966 при цели 4,987. Чтобы дотянуть до цели, нужно 1 042 дополнительные пятёрки при том, что всего объект получает около 645 оценок в месяц. Требование невыполнимо в принципе.

Запас прочности считается иначе: допустимый суммарный дефицит = `N × (5 − Цель)`. При 645 оценках это 8,4 балла — то есть **примерно две оценки «1» за месяц, и показатель уже под угрозой**. При 150 оценках не «проходит» ни одной единицы.

## 8. Что показывать в справке вместо этого

Блок «Сервис» в пообъектной справке перестраиваем так:

1. **Статус периода**: выполнен / частично выполнен / не выполнен — и числом УС в процентах.
2. **Средняя оценка и целевое значение** месяца.
3. **Счётчик негативных оценок (1–2)** — главный операционный показатель, с динамикой к прошлому месяцу.
4. **Запас**: сколько ещё негативных оценок объект «выдерживает» до потери статуса при текущем количестве оценок.
5. **Разбивка негатива по категориям** (касса, чистота, заправщик, техническое состояние) — прямая подсказка, что чинить.
6. **Комментарии клиентов к негативным оценкам** — ЛИКАРД предоставляет их справочно (п. 4.6.3) вместе с данными о транзакциях с негативными оценками, положительными и исключёнными оценками.
7. Для справок ТМ и РУ — свой набор категорий согласно их ролевому срезу.

Мотивационная формулировка для персонала: «одна оценка „Очень плохо“ стоит примерно 300 пятёрок» — честно, считается по методике и объясняет, почему важна каждая смена.

## 9. Источник данных: готовый отчёт ЛИКАРД

ЛИКАРД ежедневно нарастающим итогом и по итогу месяца (не позднее 1-го числа) автоматически рассчитывает УС в разрезе АЗС, менеджеров и директоров комплексов, управляющих комплексов, шеф-поваров, ТМ и РУ по каждому обществу и направляет отчёт на почту начальника отдела операционной деятельности АЗС, РУ и ответственного работника отдела оплаты труда.

**Состав «Отчёта о средней оценке АЗС» (Приложение №5)** — по сути готовая витрина сервиса:

РУ · ТМ/Агент · менеджер комплекса · АЗС · код АЗС · средняя оценка · целевой показатель · выполнение показателя (1 / 0,5 / 0) · количество оценок · количество оценок 3–4–5 · количество оценок 1–2 · обслуживание на кассе · работа заправщика · чистота на АЗС · техническое состояние АЗС · принадлежность · МВЗ · НПО · тип АЗС.

Два пути получения:

- **Быстрый (пилот):** автоматический разбор этого письма, как уже сделано для отчёта о простоях топлива. Даёт данные без ожидания ЛИКАРД.
- **Целевой:** те же поля в составе витрины данных плюс сырьё «АЗС × месяц × категория × балл» для ролевых срезов. Добавляем в перечень требований к витрине (БТ-В2 уточняется).

Отдельно: структура закрепления АЗС за РУ, ТМ и агентами направляется в ЛИКАРД ежемесячно до 2-го числа (Приложение №1) — **это и есть искомый исторический справочник «объект ↔ территория ↔ менеджер»** из вопроса №19 реестра. Помесячные версии этого файла закрывают задачу исторической привязки.

## 10. Качество сервиса и агенты

```
КС = (Σ негативных оценок МП + N жалоб ЕГЛ) / (Ситого / 100 000)
```

где Ситого — общее количество чеков с нефтепродуктами или нетопливными товарами по закреплённым АЗС. Чем меньше, тем лучше. Рейтинг строится по возрастанию для уровней ОНПО, РУ, ТМ/Агент, АЗС; при равных значениях присваивается общее минимальное место. Формирует УАиПП ЛИКАРД к 7-му числу.

Мультипликатор премии агента и заправщика: 1–2 кластер рейтинга — 100%, 3 кластер — 50%, 4 кластер — 0%.

Негативные оценки берутся по правилам УС; жалобы — из CRM Siebel по категории «Жалоба» (перечень тем — Приложение №12). АЗС на модернизации без остановки реализации исключаются.

**Следствия для БТ:**

- Агент (п. 1.1) — руководитель группы АЗС по агентской схеме CODO, **юридическое лицо, независимое от Группы «ЛУКОЙЛ»**. В структуре он занимает тот же слот, что территориальный менеджер («ТМ/Агент»).
- Значит, по области данных агент эквивалентен ТМ, но по режиму доступа строже: это внешний контрагент, и его изоляция — вопрос коммерческой тайны, а не только ролевой модели.
- Именованный бенчмарк, согласованный для ТМ и РУ, **на агентов не распространяется**: агент видит своё место в рейтинге и обезличенные пороги кластеров, но не значения других агентских групп.
- Если продукт показывает премиальные показатели, для агентов надо показывать КС и позицию в рейтинге, а не УС.

## 11. Терминологическая коллизия: «кластер»

Слово используется в трёх разных смыслах, и в наших документах это уже создаёт путаницу:

| Где | Что означает |
|---|---|
| Методика, Приложение №1, поле 18 | группа АЗС, управляемая по агентской схеме одним юридическим лицом |
| Методика, раздел 9 | группа рейтинга качества сервиса (1–4) для мультипликатора премии |
| Наши макеты справок v0.2 | группа сопоставимых АЗС для бенчмарка |

**Предлагаю переименовать наш термин** в «группу сопоставимых АЗС» (или «эталонную группу») везде — в БТ, макетах и блоке аналитики. Иначе на согласовании с ЛИКАРД и ИБ будет спор о том, что именно видит агент.

## 13. Что осталось уточнить

1. Для справки **объекта** берём ролевой срез «работники АЗС» (касса + чистота) или «менеджер/директор комплекса» (касса + чистота + заправщик)? От этого зависит и число, и разбивка.
2. Включаем ли **КС** в продукт наравне с УС — он нужен, если охватываем агентов и премию заправщиков. Для КС дополнительно потребуются данные ЕГЛ (жалобы) и количество чеков.
3. Как в систему попадает **целевое значение месяца**: ручной ввод администратором по распорядительному документу БРН, файл или поле витрины?
4. Берём ли на пилоте **почтовый разбор отчёта Приложения №5** как временный источник — по аналогии с простоями топлива.
5. Показываем ли пользователю **комментарии клиентов** к негативным оценкам (они содержат персональные данные третьих лиц — вопрос к ИБ).
