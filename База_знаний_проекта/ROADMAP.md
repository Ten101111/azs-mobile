# Бэклог, решения и риски

## Приоритет 0 — стабилизация до расширения пилота

| Задача | Результат/критерий готовности | Статус |
|---|---|---|
| Убрать тихий fallback на mock-данные в production | при отсутствии источника API честно сообщает отсутствие данных; есть тест | План |
| Сделать KPI import атомарным по периоду | staging/checksum/finalize; частичная загрузка не публикуется | Частично |
| Защитить эксплуатацию SQLite | WAL, `busy_timeout`, согласованное число workers, измерения блокировок | План |
| Проверить backup/restore/rollback | есть проверенный сценарий восстановления и ответственный | Частично |
| Ротировать прежние DWH-реквизиты и использовать read-only account | DWH-секретов нет на VPS, доступ только SELECT | План |
| Исправить health-check и добавить наблюдаемость | health показывает состояние зависимостей; request ID/ошибки доступны оператору | Частично |
| Зафиксировать пользователей/feedback | обратная связь не теряется; есть владелец процесса | План |

## Приоритет 1 — ценность пилота и качество данных

| Задача | Результат | Статус |
|---|---|---|
| Семантический каталог DWH | таблицы, ключи, JOIN, словарь KPI, запретные поля, версии формул | План |
| Golden SQL и сверка формул | согласованный набор эталонных запросов и проверок выручки/топлива/возвратов | План |
| Исторические организационные атрибуты | KPI соотносятся с владельцем/территорией на момент события | План |
| Data-health и административный журнал | видны свежесть, покрытие и ошибки импорта | План |
| Улучшение аналитики/сравнения | оптимизированные запросы и подтверждённые реальные источники | Частично |
| RBAC | роли и области данных утверждены, enforced в API | План |

## Приоритет 2 — AI-пилот только после P0/P1

Целевая цепочка: встроенный чат → очередь → отдельный локальный AI Worker → semantic retrieval → SQL AST Validator → Corporate DWH Agent → read-only DWH → агрегированный результат → проверяемый ответ.

Обязательные ограждения:

- модель — недоверенный генератор, валидатор принимает окончательное SQL-решение;
- только read-only SQL, allowlist таблиц и полей, лимиты времени/строк/стоимости;
- публичный VPS не имеет VPN и секретов DWH;
- новые классы запросов сначала подтверждает аналитик;
- ответы отличают факты, расчёты, гипотезы и причинные выводы;
- минимум 100 golden questions и измеримый benchmark перед расширением доступа.

## Дорожная карта из ТЗ v4

| Этап | Содержание | Оценка из ТЗ |
|---|---|---:|
| A | стабилизация платформы и импорта | 1–2 недели |
| B | семантический каталог и качество DWH | 2–4 недели |

| D | ограниченный AI-пилот | 4–6 недель |

Оценки ориентировочные, приведены для одного full-stack разработчика и действительны только после закрытия открытых вопросов.

## Открытые решения — блокеры

1. Владелец и письменное определение выручки, чеков, НТУ и топливного объёма.
2. Правила `pet_retail.volume`: как исключить нетопливные товары и учитывать возвраты.
3. Исторический справочник «АЗС ↔ территория ↔ менеджер».
4. Частота обновления DWH и SLA свежести в ручном VPN-режиме.
5. Разрешение на AI Worker и постоянный корпоративный runner.
6. Бюджет/тип GPU для пилота и production.
7. Целевая система идентификации: AD, LDAP, OIDC или SAML.
8. Матрица ролей и областей данных.
9. Срок хранения вопросов, SQL, ответов и агрегатов; правила редактирования логов.
10. Запретные для AI таблицы и поля; право обычных пользователей видеть SQL.
11. Владелец согласования новых классов AI-запросов.

## Риски, которые нельзя обходить

| Риск | Почему важен | Митигирование |
|---|---|---|
| Ошибочные формулы DWH | AI и дашборд могут уверенно масштабировать неверные выводы | владелец данных, golden SQL, сверка с эталоном |
| Частичный импорт KPI | пользователи увидят и примут неверную картину | атомарная публикация периода |
| Ошибочный SQL от LLM | риск утечки/дорогих запросов/неверных выводов | AST validator, read-only, allowlist, human approval |
| Компрометация VPS | риск доступа к внутренним данным | минимум агрегатов, отсутствие DWH secrets, hardening, backup |
| Недостаток ресурсов | AI нельзя разместить на текущем VPS | отдельный worker/GPU или отложенный AI |
| Неопределённый доступ через VPN | автоматизация может быть нереализуемой | ручной/полуавтоматический режим, затем корпоративный runner |
